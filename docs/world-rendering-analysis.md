# MM7 3D World Rendering — Terrain, Buildings & Sprites

World rendering combines outdoor terrain, buildings, sprites, rasterization, and frame orchestration.

Coverage is limited to MM7 v1.21 and the artifacts cited in Scope.

## Scope

This page covers MM7 v1.21 behavior and the binary or data artifacts cited below.
Unmarked findings are **observed**; deductions and gaps are labeled **inferred**
or **unknown** per the [documentation standard](contributing/documentation-standard.md).
Artifacts and versions not cited on this page are out of scope.
RuneHarbor-specific decisions, when present, belong in Integration notes.

Addresses are PE-image-relative (image base `0x00400000`). Original source-file
attributions come from embedded debug-assert path strings
(`D:\mm7Src_eng\MM7\Code\*.cpp`).

**Artifacts** (decompiled C, generated by the Ghidra scripts in `tools/ghidra/scripts/`):
`tools/ghidra/output/{terrain,buildings,sprites,raster3d,pipeline}.c` plus
[index.md](index.md) / `pipeline_index.md` manifests. Regenerate with
`tools/ghidra_headless.sh WorldExtract.java` and `… CallTreeExtract.java`.

## Two map types, two render paths

- **`DAT_006be1e0` = MapType**: `1` = indoor BLV (BSP dungeons), `2` = outdoor ODM (heightmap terrain + BModel buildings).
- **`DAT_00e31af0` = D3D renderer object** (null ⇒ software-only). Outdoor buildings are a D3D-favoured fast path; the warning string `"D3D version of RenderBuildings called in software!"` (`0x4ec088`) fires when this path is hit without a device.
- Shared frustum constants: near `_DAT_004d8524`, far `DAT_006bdefc`, projection scale `_DAT_004d8428`, FOV `DAT_006bdf00`, screen-space scale `DAT_006bdf04`, view clip-rect `DAT_00f8baa4/a8/ac/b0`.

## 1. Core 3D transform pipeline (`Core3D.cpp`)

Operates on an interleaved vertex array, **stride 0xC floats = 48 B/vertex**
(`[0..2]` world XYZ, `[3..5]` camera XYZ, `[6..7]` screen XY, `[8]` 1/z/depth).
Shared by terrain quads, BModel faces, and billboards.

| Addr | Role |
|---|---|
| `FUN_00436512` | **World→camera**: translate by camera pos (`DAT_00507b60/64/68`), rotate yaw (`_DAT_00507b8c/90`) + pitch (`DAT_00507b94/98`). Cross-term signs differ between software and D3D (`DAT_00e31af0`) — opposite handedness. |
| `FUN_004369ca` | Vector normalize (`1/sqrt`, scaled by `_DAT_004d8428`). |
| `FUN_00436ba6` | **Perspective project**: `screenX = camX·scale/depth + centerX`; `screenY = H − (camY·scale/depth + centerY)` (Y flipped); optional viewport clamp. |
| `FUN_00436ccb` | **Near-plane clip** (Sutherland–Hodgman): lerp pos+UV at crossings, recompute 1/z. |
| `FUN_00436ef8` | **Far-plane clip** (same, also carries depth/fog slot). |
| `FUN_00437132` | Project clipped poly to screen via `persp = DAT_006bdf04·invZ`. |
| `FUN_00424c80` / `FUN_00424e89` | Near / far clip helpers used by the building path. |

Clip-flag dispatch: `"Undefined clip flag specified"` (`0x4e93bc`) fires when the
clip byte is neither near (2) nor far (4).

## 2. Outdoor terrain (ODM: `Odmap.cpp` / `Odbuild.cpp` / `Odspan.cpp`)

## 2.1 ODM on-disk / in-buffer layout

The ODM is decompressed from `GAMES.LOD` (13 maps `out01`–`out15`, no 07/08) and
parsed by **`FUN_0047d0aa`**. The from-memory load path exposes exact offsets into
the decompressed buffer:

| In-buffer offset | Size | Block |
|---|---|---|
| `+0x80b0` | `0x4000` (16384) | **Tile map** — 128×128 bytes, one tile-index byte per cell |
| `~+0xc0b0 … +0x2c0b4` | `0x20000` (131072) | **Height grid** (128×128) + per-cell aux data |
| `+0x2c0b4` | `0x10000` (65536) | **TerNorm** — 128×128 packed terrain normals (4 B/cell), global `DAT_0075d394` |
| `+0x3c0b8` | variable | **BModel array** (3D buildings) |

So the terrain grid is **128×128 cells**. Named chunks: `"grastyl"` (tileset
selector, `0x4ec288`), `"TerNorm"` (`0x4ec280`), plus `CMAP/OMAP/BDdata/Spawn` and
`plansky%d` sky planes (from `subsystems_analysis.md`).

**Tile → texture** is indirected through tile-definition tables, not the ODM:
`data\tile.def` (text) → compiled `data\dtile.bin` (1717 entries) via class
`TileTable`; animated terrain tiles use `dtft.bin` (terrain frame table, 196
entries — water/lava cycling). A tile-map byte indexes a `TileTable` entry naming
a BITMAPS.LOD texture + flags.

**`.ddm`** is the dynamic companion (monster/item state, opened-chest flags);
loader checks both `.odm` and `.ddm` and runs a stale-state consistency check
comparing cached counts at `+0x4d8/0x4dc/0x4e0`.

## 2.2 Terrain geometry

Each grid cell `(i,j)` → one quad from four corner heights, split into two
triangles. Horizontal step is the engine's outdoor tile unit (the pervasive `<<9`
= 512-unit scale); height byte/short scaled by the standard vertical granularity
to world Z. `terrain_subdivpow2` / `terrain_subdivsize` (`0x4ea06c` / `0x4ea080`,
ini-driven) subdivide each cell into `2^pow2` sub-quads with interpolated heights
for the hardware path. Per-vertex normals are **not** recomputed — read from
TerNorm (precomputed at map-build time).

## 2.3 Terrain rendering

- **Software (`Odspan.cpp`, `FUN_00486b52`)** — a classic **active-edge-table
  scanline span builder**. Per polygon edge: compute `dy`, inverse slope `dx/dy`,
  store perspective UV + 1/z endpoints, insert into per-scanline buckets
  (`&DAT_0080c890`) sorted by X; edges bump-allocated from a pool
  (`DAT_0080c7f8`, stride 0xd). Emits per-poly records (`DAT_0080c7fc`, cap
  ~1999). Animated-texture faces (flag `0x40`) are rejected here
  (`"The Texture Frame Table is not a supported feature."`). The scanline **fill**
  (UV interpolate + palette + fog) is done by the large `FUN_00498d93` raster.
- **Hardware (`Odbuild.cpp`, `FUN_00478411`)** — see §3.3; terrain quads + BModels
  share this batch/submit path.
- **Distance fog**: per-face 5-bit fade index `0x14 − (faceOrigin·camBasis ·
  0x140000 >> 32)` clamped `[0,0x1f]`, applied via `FUN_0049b4c9`; geometry beyond
  `DAT_006bdefc` (far) is clipped. **Sky** is a separate quad (`plansky%d`,
  emitter `FUN_0045bebf`).

## 3. Buildings & indoor world (BLV + BModel)

## 3.1 BLV indoor format (`FUN_00498d93`, `Polydata.cpp`)

Largest function in the binary (7693 B). Confirms and extends the documented BLV
layout. Level-object field map (offsets into `param_1`):

| Offset | Meaning |
|---|---|
| `+0x1e8` | header buffer (**0x88 = 136 B**) |
| `+0x270/+0x274` | vertex count / array (6 B = 3×i16) |
| `+0x278/+0x27c` | **face count / array, stride 0x60 = 96 B** |
| `+0x280/+0x284` | face-texture count / array, stride 0x24 = 36 B |
| `+0x288/+0x28c` | **sector count / array, stride 0x74 = 116 B** |
| `+0x2a0` | **BSP nodes** array (`<<3` ⇒ 8 B each) |
| `+0x298/+0x29c` | sector-render data, stride 0x50 = 80 B |
| `+0x2c0/+0x2c4` | spawn points, stride 0x28 = 40 B |

- **Face (96 B)**: two plane equations — first **float `Planef`**, second
  **fixed-point `Planei`** (normals ×65536). The loader patches 6 sub-array
  pointers (`+0x30..+0x44`) into a flat face-data arena, each advanced by
  `2 + numVerts·2` bytes = the `{vertexIDs, x/y/z intercepts, U, V}` arrays.
  `+0x1d` bit `0x40` = animated texture; `+0x48` = face-texture index;
  `+0x4a` = resolved runtime texture id; `+0x5d` = vertex count.
- **Sector (116 B)**: 9 count-prefixed index lists patched from the sector arena
  (floors/walls/ceilings/portals/lights/decorations/non-BSP faces…) + a 10th
  light-reference list (`L.RLData`) from a second arena.
- **Discovered-faces bitmap**: a 0x36b-byte mask in the `.dlv` sets per-face
  "seen" flag bit. **`.dlv`** is the mutable companion (door states, spawns,
  discovered faces). Validation: `"File %s is not a BLV File"` (`0x4e96b0`).

## 3.2 BModel (outdoor 3D buildings, `BDdata` chunk)

Runtime array `DAT_006a0d48`, count `DAT_006a0d20`, **stride 0xBC = 188 B**.

- BModel header: `+0x44` vertex array ptr (12 B verts = 3×i32), `+0x4c` face count,
  `+0x54` face array ptr, `+0xac/+0xb0` origin X/Y, `+0xb8` cull radius,
  `+0x40` bit 1 = "visible this frame".
- BModel **face: stride 0x134 = 308 B**. `+0x00..+0x08` fixed-point plane normal,
  `+0x07` dword attribute flags (`0x04/0x20`=scroll-U, `0x40/0x800`=scroll-V,
  `0x2000`=invisible), `+0x44` texture id → texture record `&DAT_006f0f3c + id·0x48`
  (width `+0x18`, height `+0x1a`, scroll speeds `+0x20/+0x22`), `+0x12e` vertex
  count, `+0x12` interleaved vertex-index/U/V arrays.

> Note: `data_structures.md`'s "188 B ODM face" conflates the 188 B BModel
> *header*; the BModel *face* is 308 B.

## 3.3 Visibility & RenderBuildings

- **Indoor traversal**: front-to-back BSP walk (8 B nodes) + sector-portal frustum
  recursion; each visible sector's face-index lists feed the render list. A
  per-sector reachability bitset (`0x5ff088`, **418 B/sector**) caches
  portal-reachable sectors — consulted by **`FUN_004c0703`** (Vis query: type 1
  facet, 2 decoration, 3 portal/door with must-have/must-not masks; LOS via
  `FUN_00438bce`). `FUN_004c1b1c` = `CVis::Get`; `FUN_004c2503` = build result
  list (all / unique, 12 B hit records).
- **Outdoor cull**: `FUN_00478411` iterates all BModels, each gated by
  **`FUN_0047908d`** (angular + distance cull: reject if `dist >
  far+0x800` or outside half-FOV `(FOV<<11)/360/2`), then per-face back-face cull
  via the plane builder **`FUN_00482174`** (edge cross-product → normal + distance,
  sign of `N·camPos`).
- **Clipping**: outdoor faces + all dynamic light geometry use the Core3D frustum
  clipper; indoor dynamic light-polys fall back
  (`"Lightpoly builder native indoor clipping not implemented"`, `0x4e9380`) —
  indoor faces are clipped by the portal/BSP system itself.

**`FUN_00478411` (RenderBuildings) per-frame flow**: cull BModels → for each
visible face: resolve texture (animated via `FUN_0044e1c6`), apply scrolling-UV
offsets (`GetTickCount()>>4 ·` scroll speed), build a per-poly descriptor in
`&DAT_0077eab8` (stride 0x10c, cap `0x7ce`), transform+project verts
(`FUN_00436512`/`FUN_00436ba6`), compute per-face diffuse light level
`0x14 − (N·sunDir)` clamped `[0,0x1f]` (sun dir `DAT_006a19a0/a4/a8`), near/far
clip, then rasterize via **`FUN_004a1fe0`**.

**Rasterizer (`screen16_3d.cpp`)**: `FUN_004a1fe0/264c/2f50` build a D3D
`TLVERTEX`-style buffer at `&DAT_0077e448` (stride 0x40: x,y,z,rhw,color,specular,
u,v) and call the device vtable — `+0x98` SetTexture, `+0x70` DrawPrimitive
(`6`=triangle fan, FVF `0x1c4`), `+0x58` SetRenderState. A second alpha pass
applies lightmap/colored-fog blend when `DAT_00ef50c8` is set. In software mode
they write 16-bit pixels directly (RGB565/555 chosen by `DAT_00e31b38`).

## 4. Sprites & billboards (items / monsters / NPCs)

## 4.1 Assets

`SPRITES.LOD` (+ low-res `spriteLO.lod`) opened in master init (`0x465672`).
External-only LOD layout (dedicated `sprite_lod_archive`): per entry
`ImageFileHeader` (48 B) + zlib indexed pixels + separate 768 B palette. **Index 0
= transparent**. Hardware texture lists cached in `d3dsprite.hwl` / `d3dbitmap.hwl`.

## 4.2 Frame tables — `CSpriteFrameTable::load` (`FUN_0044dabe`, `sft.txt`)

Two-pass text parse. Object members: `[0]` frame count, `[1]` group count, `[3]`
**S-Frames** array (**0x3C = 60 B/record**), `[4]` P-Frames (group index ptrs),
`[5]` E-Frames (group map shorts).

S-Frame record: `+0x00` icon name[12], `+0x0C` sprite base name[12] (SPRITES.LOD
key), `+0x28` animation length, `+0x2C` flags A (bit 1 = continues into next group
frame, bit 2 = multi-frame group, bit 0x10/0x1E000 = type), `+0x2D` flags B (bits
0x01–0x80 = **Mirror0..Mirror7**), `+0x30` group/facing count, `+0x32` per-frame
duration, `+0x36` time increment, `+0x38` cumulative group time (post-pass).
Tokens `"Luminous"`, `"Mirror0".."Mirror7"` set the flags. A post-load pass sums
`+0x36` across each contiguous group into `+0x38`, then sorts groups by name.

## 4.3 Frame & facing selection (`FUN_0044e1c6`)

```cpp
rec = frames[group]
if (rec.flags & 1)==0 || rec.groupLen==0:  return rec.frameId   // static (ground item)
t = (globalTick >> 3) % rec.groupLen
while (rec.increment < t): t -= rec.increment; group++; rec = frames[group]
return frames[group].frameId

```

Facing is resolved upstream: octant from `wrap(objYaw − camYaw)` selects the base
group + a mirror flag; the **5-sprites→8-facings** scheme covers the other 3
octants by horizontal flip (Mirror0..7 flags → flip bit `+0xC1C`, see below).

## 4.4 Billboard projection — `PolyProjector` (`FUN_0049b719`)

Builds a screen-aligned quad in a ring of **0xC20-byte** poly records (cap **1024**
projected / 1500 registered):

1. Reject if depth == sentinel `_DAT_004d84e8`.
2. Store flip bit `+0xC1C = (flags & 2)` (mirrored facing).
3. Perspective scale = `focal/depth`; multiply into the view-matrix right/up axes →
   cached scaled screen axes.
4. Four corners `center ± scale·halfW·right ± scale·halfH·up`, UVs (0,0)/(0,1)/
   (1,0)/(1,1); pivot offsets from header `+0x30/+0x34` (feet anchor) applied via
   `FUN_004a4fd8`.
5. Model→view per corner, then `FUN_00498042` clips (`FUN_00436ccb/ef8/132`) and
   emits.

Indoor sprites use the structurally identical `Light.cpp` chain
(`FUN_0045bc40`/`FUN_0045bebf`) writing the indoor poly buffer.

## 4.5 Depth sort & blit

- **Occlusion**: `FUN_0049be13` (float) / `FUN_0049bc74` (fixed) AABB-test the
  sprite's projected extents against candidate facets, compare sprite depth vs each
  facet plane distance, and record overlapping facets for per-facet light/decal
  clipping. Ordering follows BSP/sector traversal + per-facet z-test (no global
  painter sort); the GPU path additionally writes per-vertex 1/z into the
  z-buffer.
- **Software vs hardware**: `FUN_004ac723` (`AddSprite`/`hardSprites`) registers
  sprites in a 0x28-byte table (cap 1500); D3D path uploads via
  `FUN_004a4fd8` (`HiScreen16::LoadTexture`), software path builds column tables
  (`FUN_004ac5e1`). Emit via `FUN_004a1fe0` (DrawPrimitive, alpha-test `0x10` /
  alpha-blend `0x1c`); renderstate block set by `FUN_0049c28d`.
- **Transparency**: palette index 0 → alpha 0 (SW skips, HW alpha-tests).
  `FUN_0048a3a2` builds/caches up to 50 per-tint lit palettes (`"pal%03i"`) for
  fog / day-night / status tints.

## Open uncertainties

- Exact split of the ODM `0x20000` height region (raw heights vs precomputed
  per-vertex data) and TerNorm encoding (quantized vs 3×float) are size-inferred.
- World cell size (512) / height scale are the engine-standard `<<9` constants but
  the literal wasn't isolated in the terrain slice — verify against the height-sample
  helper before hardcoding.
- BSP-node (8 B) internal layout (split-plane vs child links) and the exact naming
  of the 9 sector index-lists are inferred from MM7 convention, not byte-confirmed
  (the BSP-walk function wasn't in the extract set).
